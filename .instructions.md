# flutter_ilib Instructions for AI Agents

## Project Overview

**flutter_ilib** is a Flutter plugin wrapper for the [iLib](https://github.com/iLib-js/iLib) internationalization library. The project provides Dart APIs for locale management, date formatting, and case conversion across 100+ locales.

### Key Facts

- **Language**: Dart/Flutter
- **Version**: 2.0.0
- **Type**: Flutter Plugin Package
- **Platforms**: Linux, WebOS (extensible)
- **Main Dependencies**: flutter:sdk, logging, plugin_platform_interface

## Core Classes & Responsibilities

### 1. ILibLocale (lib/ilib_locale.dart)
- **Responsibility**: Parse, validate, and normalize locale strings per BCP-47 standard
- **Key Methods**: getLanguage(), getRegion(), getScript(), getSpec()
- **Validation**: Supports language-only, language-region, language-script-region, AND region-only (NEW in v2.0)

### 2. ILibLocaleInfo (lib/ilib_localeinfo.dart)
- **Responsibility**: Retrieve localization data (region name, timezone, currency, etc.)
- **Data Source**: assets/locale_data/ JSON files (100+ files)
- **Key Methods**: getRegionName(), getTimeZone(), getDecimalSeparator(), getFirstDayOfWeek()

### 3. ILibDate (lib/ilib_date.dart)
- **Responsibility**: Format dates according to locale conventions
- **Key Methods**: format(ILibDateFmtOptions)
- **Options**: locale, length ('short'|'medium'|'long'|'full'), useNative

### 4. ILibCaseMapper (lib/ilib_casemapper.dart)
- **Responsibility**: Perform locale-aware case conversion
- **Key Methods**: toLowerCase(), toUpperCase()
- **Example**: Turkish 'İ' (capital dotted I) → 'i̇' (lowercase dotted i)

### 5. ILibJS (lib/ilib_init.dart)
- **Responsibility**: Manage JavaScript runtime and locale data caching (Singleton)
- **Key Methods**: getLocaleData(), _loadLocaleData(), _deepMerge()
- **Pattern**: Singleton with two-tier caching (files + merged locales)

## Data Loading Strategy

### Locale Path Resolution

Input → Parse with ILibLocale → Generate paths in priority order → Load and merge:

```
root.json (always first)
           ↓
{language}.json
           ↓
und_{script}.json (if script)
           ↓
{language}-{script}.json (if both)
           ↓
und-{region}.json (if region)
           ↓
{language}-{region}.json (if both)
           ↓
{language}-{script}-{region}.json (if all three)
```

More specific files override earlier values via deep merge.

### Important: Region-Only Locales (v2.0+)

Inputs like `'MK'` (no language) are now valid:
- `isValidLocale('MK')` → true
- `getJSONDataPaths('MK')` → `['root.json', 'und-MK.json']`
- File: `assets/locale_data/und-MK.json`

- Check `lib/internal/ilib_utils.dart` for utility functions
- Update `isValidLocale()` for new validation rules
- Update `getJSONDataPaths()` for new path patterns
- Always update corresponding tests

## Key Changes in v2.0.0

This project originally loaded iLib JavaScript code at runtime via **flutter_js**. The current effort is to remove that JS dependency entirely by **porting iLib's locale handling logic directly into Dart**, evolving the package into a pure Dart/Flutter implementation.

### Background

The original architecture embedded a JavaScript engine through `flutter_js`, which introduced per-platform build complexity and runtime performance overhead. To address this, the core iLib functionality — locale parsing, data loading, and information lookup — is being rewritten in native Dart.

### Current Porting Status

- **Completed**: `ILibLocale` (locale string parsing and validation), `ILibLocaleInfo` (locale data lookup), `ILibDate` (date formatting), `ILibCaseMapper` (case conversion)
- **In Progress**: Locale data path generation logic (`ilib_utils.dart`), edge case handling such as region-only locales


### Guidelines When Porting

The Dart implementation must match the behavior of the original iLib JavaScript code exactly. Reproducing existing JS behavior takes priority over adding new features. All ported code must produce the same results as the original JS-based test cases.

## Common Issues & Solutions

### Locale Data Not Loading
- Check: `isValidLocale(locale)` returns true
- Verify: `getJSONDataPaths(locale)` returns expected paths
- Confirm: Files exist in `assets/locale_data/`

### Analysis Warnings
- Run: `flutter analyze` and fix immediately
- Check: pubspec.yaml for deprecated dependencies
- Update: analysis_options.yaml if needed

### Test Failures
- Run: `flutter clean` then `flutter pub get`
- Rerun: `flutter test --verbose`
- Check: Recent changes to path generation or validation

## File Structure to Know

```
lib/
├── flutter_ilib.dart         # Public API exports
├── ilib_locale.dart          # Locale parsing (1000+ lines)
├── ilib_localeinfo.dart      # Locale info lookup
├── ilib_date.dart            # Date formatting
├── ilib_casemapper.dart      # Case conversion
├── ilib_init.dart            # JS runtime (ILibJS singleton)
└── internal/
    ├── ilib_utils.dart       # getJSONDataPaths(), isValidLocale(), etc.
    └── logger/               # Logging interface

assets/locale_data/
├── root.json                 # Base defaults for all locales
├── en.json, ko.json, ...     # 100+ language-specific files
├── und-US.json, und-MK.json  # 100+ region-specific files
└── en-US.json, ko-KR.json    # 200+ full locale files

test/
├── basic/
│   └── flutter_ilib_utils_test.dart
├── casemapper/
└── localeinfo/
    ├── localeinfo_test.dart
    └── localeinfo_dayofweek_test.dart
```
